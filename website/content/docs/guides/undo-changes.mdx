description: "Revisit an earlier prompt, restore opt-in SDK file checkpoints, and keep git as your outer safety net."

Conversation rewind and file restore are separate operations. Use `/rewind` to change what the model remembers, and git or explicitly enabled SDK file checkpoints to change what is on disk.

<Callout type="warn">
Rewinding a conversation does not undo file edits, shell commands, API requests, sent messages, or other external effects. Inspect the workspace before resending an earlier prompt.
</Callout>

## Edit an earlier prompt

<Steps>
<Step>

Wait until the current turn has stopped. Run `/rewind`, or press Esc twice at an empty, idle REPL prompt.

</Step>
<Step>

Select an earlier user message from the picker. Cancel the picker if you want to keep the current conversation.

</Step>
<Step>

The chosen prompt and everything after it are removed from the active conversation. The selected prompt's text is loaded into your input buffer. Edit it and press Enter to resend.

</Step>
</Steps>

Conversation rewind is available on both the Anthropic and OpenAI-compatible providers. It requires an interactive terminal and cannot run while a turn is in flight. Tool-result messages are not offered as user prompts. A prompt without text, such as an image-only turn, is not a rewind target.

Rewind is a conversation branch operation, not a transaction rollback. For example, if a discarded turn created a file, the model may no longer remember creating it, but the file remains. Tell the model about the current disk state before asking it to repeat the work.

## Restore file checkpoints from the SDK

File checkpointing is an opt-in `AgentConfig` capability, disabled by default. It is implemented for both providers. There is not currently a CLI checkpoint toggle or a `/rewind files` picker. Applications embedding afk enable it when they create a session.

Checkpoints save a file's state before the first supported write to that path in a turn. Supported tools are `write_file`, `edit_file`, and a non-dry-run `patch_apply`. Shell changes are not captured.

<Steps>
<Step>

Create a session with checkpointing enabled:

```ts
import { AgentSession } from 'agent-afk';

const session = new AgentSession({
  model: 'sonnet',
  enableFileCheckpointing: true,
});
```

</Step>
<Step>

Keep the completed turn's `metadata.userMessageId`. It is the public checkpoint target, not the conversation picker's numerical turn index.

```ts
const reply = await session.sendMessage(
  'Create a short draft in draft.txt using write_file.'
);
const checkpointId = reply.metadata?.userMessageId;
```

</Step>
<Step>

Preview the restore, review its paths, then explicitly apply it:

```ts
if (!checkpointId) throw new Error('No checkpoint target was returned.');

const preview = await session.rewindFiles(checkpointId, { dryRun: true });
if (!preview.canRewind) throw new Error(preview.error);
console.log(preview.filesChanged);

// Apply only after your application or user has approved the preview.
const restored = await session.rewindFiles(checkpointId);
if (!restored.canRewind) throw new Error(restored.error);
console.log(restored.filesChanged);

await session.close();
```

</Step>
</Steps>

In a streaming application, the `done` event's metadata carries the same checkpoint ID. Stop the turn before restoring.

### What a file restore does

For each tracked path, restore writes the saved bytes and mode, or deletes the file if it did not exist before that turn. Current write grants and protected-path rules are rechecked. A historical checkpoint does not grant new access.

A checkpoint covers paths touched in that turn, not a whole-workspace snapshot. It does not roll back unrelated files touched only by later turns. Restoring an old checkpoint can overwrite newer work at a tracked path, so inspect the diff and preview before applying it.

Restoration is per-file, not transactional. A failure can report some files already changed. Check `canRewind`, `error`, and `filesChanged` rather than assuming all-or-nothing success.

Checkpoint state lives under the configured AFK state directory at `file-checkpoints/<sessionId>/`. Saved content is deduplicated within the session. There is no automatic checkpoint retention or garbage collection policy yet. Checkpoints are not a security boundary against another process running as your user.

## Keep git as the outer safety net

Before a significant change, start from a known commit and use a feature branch or [managed worktree](/guides/worktrees). Git covers changes made through shell tools as well as typed file tools, provided you actually commit or otherwise preserve the work.

Inspect first:

```sh
git status --short
git diff
git diff --staged
```

Use the diff to distinguish the agent's changes from your own before restoring anything. Untracked files, ignored files, and external effects are not protected merely because you are in a git repository. Preserve anything irreplaceable before a destructive restore or worktree removal.
