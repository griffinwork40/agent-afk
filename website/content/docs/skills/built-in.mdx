title: "Use a core skill"
description: "Pick a built-in AFK skill for onboarding, feature work, or service setup."
---

Core skills are registered by AFK itself rather than discovered from a user `SKILL.md`. Start with `/get-started` for onboarding, or choose a targeted workflow below. Run `/skills` in the REPL to see the skills available in your current session.

| Skill | Best for | Effect |
|---|---|---|
| `/get-started` | First session | Checks setup and guides you to a first task in the current session. |
| `/mint <idea>` | A feature or refactor with a clear goal | Orchestrates specification, research, implementation, and verification; pauses for spec approval. |
| `/service-setup` | A bot or daemon that should survive logout or reboot | Checks prerequisites and guides service installation using the supported service command. |
| `/telegram-setup` | First Telegram bot configuration | Guides human token entry and verifies the bot and chat allowlist. |

`/service-setup` and `/telegram-setup` use a forked context. The service workflow supports macOS LaunchAgents, Linux systemd user units, and Windows Task Scheduler. Service installation changes persistent OS startup behavior, so confirm the requested target before proceeding. `/mint` can write code and take later shipping steps; inspect its spec and approval boundary. A code diagnosis workflow is also shipped as the bundled `/diagnose` skill, rather than being a separate core TypeScript handler.

Internal-only skills do not appear in ordinary public skill listings. This page deliberately lists public workflows, not private operator extensions. For procedures including review, PR repair, and project orientation, see [Bundled skills](/skills/bundled).
