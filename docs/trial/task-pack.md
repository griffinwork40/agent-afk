# Task pack

Work in a repository you own. Start `afk i` **from the repo root**, then type one quoted prompt below without the quote marks. Substitute a real module, test, or small change from your repo where indicated. **⚠ Replace:** bracketed descriptions in prompts such as `[a module you choose]` and `[a failing test]` are not literal paths or runnable shell commands. Pick an actual target before sending. Never run an agent-proposed command you cannot explain, and approve publishing or persistent automation explicitly. Times are planning ranges, not promises. Check the result yourself; an AFK Done block is not evidence by itself.

| # | Prompt to type in the REPL | Verified result | Your check | Time | Capability |
|---|---|---|---|---|---|
| 1 | "Explain how [a module you choose] fits into this repo. Cite the relevant files and identify one test or call site; do not edit anything." | Correct explanation with paths and no edits. | Open two cited files, check the claimed call or test; inspect `git diff`. | 10 to 20 min | Code navigation, grep and files |
| 2 | "Find one test I can run in this repo, run it, and explain what it tests. Do not change source." | Actual test command, exit status, and grounded explanation. | Rerun the same command yourself and compare the result; inspect `git diff`. | 10 to 25 min | Shell and test verification |
| 3 | "Fix [a failing test you observed] with the smallest justified change. Explain the cause first, then run that test and relevant surrounding tests. Do not commit." | The previously failing test now passes without unrelated changes. | Run the failing command yourself; review `git diff` and broader tests. If no failing test exists, skip rather than fabricate one. | 20 to 60 min | Diagnosis, edits, tests |
| 4 | "Add [a small behavior you choose] with a test covering its new behavior. Keep existing behavior intact, and show the commands and results. Do not push." | Behavior works and new test fails without the change or otherwise demonstrates it. | Inspect code and test, run targeted and relevant suite, review diff. | 30 to 75 min | Feature, test authoring, verification |
| 5 | First type "Investigate [a moderately involved issue you choose]. Write a short checkpoint of current evidence and next checks to a file in this repo, then stop for my go-ahead. Do not commit or push." **Wait for the turn to finish** and confirm the checkpoint exists. Next type "Continue the investigation from the checkpoint; run the relevant checks. Do not commit or push." Close the terminal window **during this second, active turn**. On the next day, reopen a terminal, return to the *same repository directory*, run `afk i`, type `/resume`, choose the saved session, confirm the preview with Enter, then type "The previous turn was interrupted. Read the checkpoint and current diff before continuing; do not assume an interrupted tool completed. Re-run verification and report what remains." | Recovery distinguishes the saved first turn from interrupted work, rechecks filesystem and tests, and reaches a verified result or accurate Blocked receipt. | Inspect checkpoint and `git diff` before and after; rerun reported tests. If no saved session appears, note it as a failure and restart from the checkpoint in a new session. | 20 to 60 min active, plus next-day gap | Session autosave and `/resume` |
| 6 | "Run a suitable longer test or build for this repo in the background, then report its actual final exit status and summarize failures. Do not change files." | Completed job has an exit status and output consistent with the command. | Re-run or inspect the same test/build output; do not count merely starting the job. | 15 to 45 min | Background process and result delivery |
| 7 | "Prepare a reviewable PR for [your already verified small change]. Show the diff and check results first. Ask me before pushing or opening the PR." | If explicitly approved, PR URL and checks match the diff; otherwise a local, reviewable change with no publication. | Open the PR yourself and inspect changed files and CI; if not approved, inspect local `git diff`. | 20 to 60 min | Git workflow and external-action boundary |

Task 5 is the **required interruption** for this trial, not a test of graceful shutdown. The current turn may not be replayable after a terminal is killed. A prior completed turn autosaves (`src/cli/commands/interactive/loop-iteration.turn-run.ts:110-126`), and `/resume` lists saved sessions, preferring the current working directory; on a TTY it shows a selection picker then a confirmation preview. If nothing was saved yet, the checkpoint file is the recovery path. If the tester wants a direct launch rather than the picker, `afk i --continue` continues the latest persisted session in the current directory, but it may not be the intended one when several exist. Do not silently use it in that case. See `src/cli/slash/commands/resume.ts:269-346`, `src/cli/commands/shared-command-options.ts:112-114`, and `src/cli/commands/interactive/interactive.cleanup.ts:205-226`.

Task 6 uses the model's `bash` background mode; the tester need not know a project-specific command in advance. The `!&` REPL shell shortcut is another background path, but its result reaches the model on the next message (`src/cli/commands/interactive/shell-passthrough.ts:1-24,55-84`). Do **not** close the REPL while a background job is running. Task 7 may trigger external actions, so withhold approval until checks and diff are reviewed. For every task, record the final Done/Blocked receipt and whether you understood it without a facilitator translation.
