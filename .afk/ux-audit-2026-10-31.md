## Genuine Gaps Found and Fixed

### 1. Summary-mode thinking indicator (NEW)

**Gap:** In `'summary'` mode, the `thinking-live` overlay slot returns `''` (lifecycle.ts:119). During a pure thinking phase (before any tool or content), the user sees nothing. Thinking can last 5-30+ seconds.

**Fix:** Added three pieces:
- `ThinkingLane.activeThinkingElapsedMs()` — returns elapsed ms only during the real thinking window (stops at `markEnded()`, so tool-execution time is never conflated)
- `checkThinkingAnnotation()` — 1 Hz change-detection tick mirroring `checkTtfbAnnotation`, with 2s grace period
- Progress-banner slot branch — renders `◦ thinking · Xs` when thinking is active and no other banner content is present

**Before:**
```
[nothing for 15 seconds]
◆ thought for 15.2s · 3,842 tokens
Here's what I found...
```

**After:**
```
  ◦ thinking · 3s       ← appears after 2s, updates every second
  ◦ thinking · 14s      ← clears when markEnded() fires
◆ thought for 15.2s · 3,842 tokens
Here's what I found...
```

**Transitions verified by tests:**
- Returns null before any thinking chunks arrive
- Returns elapsed ms during active thinking
- Returns null after markEnded (tool dispatch / content)
- Returns null after collapse (turn finalization)
- Clamps negative values (NTP step-back guard)
- 1 Hz change detection (fires once per second, not per 80ms tick)
- Clears annotation when thinking ends
- No-ops in live/digest mode (those modes have the thinking-live slot)
- No-ops for non-TTY

**Files changed:** `thinking-lane.ts`, `stream-renderer-lifecycle.ts`, `stream-renderer.ts`

### 2. Unknown-error hint (NEW)

**Gap:** The `unknown` fallback in `classifier.ts:224-231` had no `hint` field. Users seeing an unclassified error got the raw message with no guidance.

**Fix:** Added `hint: 'If this keeps happening, check \`afk trace show\` for the full error or try \`afk doctor\`.'`

**File changed:** `classifier.ts`

### 3. Dead-zone integration test fixture (FIX)

**Gap:** `stream-renderer-dead-zone-integration.test.ts` created a LifecycleContext via `as unknown` cast without `lastThinkingAnnotation`, causing `checkThinkingAnnotation` to read `undefined` and return a false dirty signal.

**Fix:** Added `lastThinkingAnnotation: ''` to the test fixture.

## Verification Classification — Separate Follow-up

The `doneHasCorroboratingEvidence()` classification is used on Telegram (`afk-push.ts:147-183`) but not in the CLI verdict card. The devils-advocate wave correctly identified two remaining risks:

1. **Subagent-delegated tests** are invisible to the parent's `classifyDoneEvidence` (agent/compose/skill excluded from `DONE_EVIDENCE_TOOLS` at `done-evidence.ts:44-52`)
2. **No content hash** — `lfVerification` records no SHA, so file changes through untracked means are undetectable (status-quo pin test at `lf-immediate.artifact-stale.test.ts:176-196`)

These should be fixed as standalone correctness improvements to the classification before surfacing it in the CLI verdict card. Filed as a separate scope.
